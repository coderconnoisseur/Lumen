# Forecast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A measured, explainable forecast (this month + next 3) used by a new Plan · Forecast page and by Home, Budget and Ask.

**Architecture:** A pure module `backend/ai/forecast.py` (transaction dicts in, numbers out; no DB, no LLM): detected bills are projected onto their due days, and two methods (a robust average, a Holt linear-trend model) compete on everyday spending, scored by a backtest over the user's past months. A thin route serves it (F2); the page renders it (F3). An offline eval suite gates accuracy in CI.

**Tech Stack:** Python 3.11, numpy/pandas only (no statsmodels), FastAPI, SQLAlchemy; Next.js 14 + Tailwind v4; pytest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-28-forecast-design.md` (mockup `docs/superpowers/specs/2026-10-28-forecast/forecast.html`).

## Global Constraints
- Horizon: this month + the next 3 (4 months).
- Bills = active recurring charges of kind `bill` or `subscription` (not cancelled / not_a_bill, not `possibly_stopped`); kind `recurring` stays everyday.
- The two methods compete on everyday spending only; bills are identical in both.
- Backtest: up to the last 6 complete months; score = median absolute % error of the whole-month total; mid-month cut = forecast from data up to the 15th.
- Choice per user: lower score wins; ties → bills + everyday; fewer than 3 backtestable months → bills + everyday and "too little history".
- Gates: chosen method median error ≤ 10% whole-month, ≤ 12% at the mid-month cut, in-range rate ≥ 60%.
- No LLM anywhere in the forecast or the "why" line; every number in a "why" line equals a number in the payload.
- PRs into `refactor`, one at a time, never stacked; no Claude attribution.

## Review Focus
1. A brand-new account (0–1 months of data) → the forecast says it can't forecast yet; nothing crashes, no fake range. (Task 3 test.)
2. A refund-heavy month (negative net everyday spend) → level never goes below 0, range low ≥ 0. (Task 2 test.)
3. A huge one-off in a history month (₹1,00,000 laptop) → the robust method's next-month level isn't dragged up by it. (Task 2 test.)
4. Today = the last day of the month / the 1st → current month split has 0 / all days left, no division by zero. (Task 3 test.)
5. A yearly bill due in month 3 and a weekly bill → counted on the right days, once each. (Task 1 test.)

### Task 2: everyday spending — two methods

**Interfaces:**
- Produces:
  - `monthly_everyday(txns, bills, today, months: int = 6) -> list[tuple[str, float]]` — complete months before `today`'s month, oldest first, net everyday total (non-bill txns; refunds net out), only months that had spend; at most `months`.
  - `robust_level(history: list[float], ahead: int) -> tuple[float, float, float]` — (level, low, high): level = median of history (trimmed mean if the backtest prefers it; builder's call, record as a Ruling); low/high = 20th/80th percentiles, widened by `ahead * 5%` of level each side; all clamped ≥ 0.
  - `holt_level(history: list[float], ahead: int) -> tuple[float, float, float]` — Holt's linear trend (alpha 0.5, beta 0.2 unless the backtest says otherwise), forecast `ahead` steps after the last history month; range = ± 1.28 × residual std × sqrt(ahead); clamped ≥ 0.
  - `METHODS = {"bills_everyday": robust_level, "holt": holt_level}`; display names `{"bills_everyday": "Bills + everyday", "holt": "Statistical (Holt)"}`.
  - Both return `None` when `len(history) < 2`.

- [ ] **Step 1: failing tests** `test_robust_ignores_a_one_off` (history [20k, 21k, 100k, 19k] → level < 30k), `test_levels_never_negative` (refund-heavy [-500, 200]), `test_holt_follows_a_trend` ([10k, 12k, 14k, 16k] ahead 1 → between 16k and 20k), `test_ranges_widen_further_out` (ahead 3 wider than ahead 1), `test_too_little_history_returns_none`, `test_monthly_everyday_excludes_bills_and_this_month`.
- [ ] **Step 2:** FAIL. **Step 3:** implement. **Step 4:** pass. **Step 5:** commit `feat: forecast: everyday spending, robust average vs Holt`.

### Task 3: the forecast for one method

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces `forecast_months(txns: list[dict], recurring: list[dict], today: date, method: str, *, budgets: dict[str, dict] | None = None, income: float | None = None) -> dict | None`:
  - `None` when the method returns None (too little history).
  - `{"months": [4 × {month "YYYY-MM", forecast, low, high, bills, everyday, budget, income, left, over_budget, categories: [{category, spent, forecast, budget}]}], "current": {spent_so_far, bills_still_due: {count, amount}, everyday_rest, days_left}, "daily": {actual: [cumulative per day to today], path: [cumulative per day today..end], low, high}}`.
  - Current month: forecast = spent so far + bills still due + everyday daily rate × days left (daily rate = everyday level / days in month); low/high scale the everyday rest only. Months ahead: bills_in_month total + everyday level (ahead 1–3).
  - Categories: bills by their category; everyday split by each category's share of the history's everyday spend; current month also has `spent`.
  - `budgets`: `{month: {"total": float|None, "categories": {name: limit}}}` (as `api/budget.limits_in_force` + `monthly_budget`); `budget` null when absent; `over_budget` = forecast > budget (null without budget). `left` = income − forecast, null without income.
  - Daily path: actual cumulative to today, then + bills on their days + daily everyday rate.

### Task 4: backtest, choice, accuracy

**Interfaces:**
- Produces:
  - `backtest(txns, today, method, *, cut_day: int | None = None, months: int = 6) -> list[dict]` `{month, actual, predicted, low, high}` — for each of the last `months` complete months M with spend: recurring detection and history built only from txns before M (or before M's `cut_day`+1 for the mid-month cut, where the prediction is spent-to-cut + the rest); predicted = whole-month total.
  - `score(results) -> dict` `{median_error_pct, in_range_pct, months_tested}` (median of |predicted−actual|/actual × 100, rounded to 1 dp).
  - `choose(txns, today) -> dict` `{method, accuracy: {method, median_error_pct, months_tested, in_range_pct, tried: [{method, label, median_error_pct}]}}`; fewer than 3 tested months → `{"method": "bills_everyday", "accuracy": {"months_tested": n}}`; ties → bills_everyday.
  - `forecast(txns, recurring, today, *, budgets=None, income=None) -> dict | None` = `choose` + `forecast_months` with the chosen method + `accuracy` + `items` (bill items with `monthly_equivalent`, weekly×52/12, yearly/12).
- [ ] **Step 1: failing tests** `test_backtest_uses_only_the_past` (a txn dated inside M never feeds M's prediction: monkeypatch/inspect), `test_score_median_and_range`, `test_choice_prefers_lower_error_and_ties_go_to_bills_everyday`, `test_too_little_history_says_so`, `test_mid_month_cut_counts_spent_to_the_cut`.
- [ ] **Steps 2–5**; commit `feat: forecast: backtest each method and keep the better one`.
