# BYOK (Bring Your Own Key) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user pastes a key for OpenAI, Anthropic, Gemini, Groq or OpenRouter. From then on Ask Lumen, invoice reading and email parsing use that key, with a model Lumen picks from a curated list. Users without a key get a free allowance on the platform key (the owner's Groq), and then a prompt to add their own.

**Architecture:** All five providers speak OpenAI chat-completions (Anthropic through its OpenAI compatibility layer, Gemini through its `/v1beta/openai` endpoint), so `llm/client.py` keeps its single request shape. There are two new adapters (`openai`, `anthropic`) and one new hook (`Provider.adapt(payload)`) that drops fields a provider rejects. A `byok` section in `llm/registry.yaml` lists the allowed models per provider and role. `Entry` gets an optional `key` (not shown in `repr`). A new `llm/keys.py` holds a contextvar with the request's user and engine. Flask sets it in `require_auth`, the FastAPI handlers and the email poller set it explicitly, and when it is set `complete()` builds the chain from the user's keys. A failure on a user's key is written to `user_keys.last_error` and flagged on the error (`e.user_key`). The poller stops retrying on that flag, and routes show "your key was rejected". The free allowance has two parts: questions are counted by the existing limiter for every user without a key (today only demo users are counted), and invoice reads are capped by counting the user's `review_items`.

**Tech Stack:** Flask + FastAPI, SQLAlchemy, `requests`, `cryptography` (Fernet via `utils/crypto.py`), PyYAML, pytest; Next.js 14 + TypeScript.

**Spec:** `docs/direction/specs/SPEC-BYOK.md` (APPROVED by the owner, 2026-10-14).

## Global Constraints

Copied verbatim from the spec:

- "Users pick a **provider** and paste a key; Lumen picks the model per role from that provider's list (an "advanced" dropdown may choose among the listed models, never outside them). Updating the list is a one-line change; retired models drop off it."
- "**Roles keep their meaning:** `agent` (Ask Lumen; strongest tool-calling model on the list), `vision` (invoice reading), `text` (cheap structured jobs: email body parsing, categorising). A role can come from a different provider than the agent if the user adds two keys."
- "**Keys:** stored per user, encrypted (`utils/crypto.encrypt_secret`), never returned to the browser (only the last 4 characters), validated on save with one cheap call (list models / a 1-token request), deletable. New table `user_keys(user_id, provider, key_enc, created_at, last_ok_at, last_error)`."
- "Keys are secrets at a trust boundary: encrypted at rest with a dedicated `EMAIL_ENCRYPTION_KEY`-style key (`KEYS_ENCRYPTION_KEY`), never logged (mask to last 4), sent only to their provider, rate-limited validation."
- "a provider without vision falls back to another key the user has, else the platform key"
- "Cassette replay keys on provider+model, so recorded evals are unaffected."
- "Keyless users (demo and new accounts) get a free allowance on the platform key, then a prompt to add their own key. The allowance size is a config value (start: the demo's 20 questions/day plus 20 invoice reads, total, per account)."
- Providers: "**OpenAI, Anthropic, Google Gemini, Groq, OpenRouter** (OpenRouter restricted to the listed model ids)."

Plan rules:

- With a user key for a role, the chain contains **only that user's providers** and never falls back to the platform key. A rejected key must surface to the user instead of quietly spending the owner's quota. The platform key is used only for a role that none of the user's keys covers (for example vision for a Groq-only user).
- Without a user in context (evals, scripts, CLI), `complete()` builds exactly the chain it builds today. **Eval cassettes are NOT re-recorded in this plan.** `tests/test_eval_selftest.py` must stay green.
- The platform `agent` role is the tier's `text` chain (today's behaviour). Only the `byok` catalogue has `agent` rows.
- A user key is a "key error" when the final failure on a user entry has kind `auth`, `insufficient_credits` or `config` (a 403 "model not available to this key" maps to `config`).
- No key, or part of a key, in any log line, API response or error detail. Mask provider error text with `keys.mask(text, key)`.
- Saving refuses (503 `keys_unavailable`) when encryption is unavailable, so a key is never stored in plaintext.
- UI stays bare-bones (inner-app revamp later): reuse `@/components/ui/*`, and no layout shift.
- Git: no AI attribution. One PR per task into `refactor`. The branch prefix for each is `feat/byok-<n>`.
- Ponytail: shortest correct diff. No new dependencies.

## Review Focus

1. **A revoked or invalid user key in Ask Lumen.** The user sees "Your OpenAI key was rejected. Update it in Settings." (HTTP 400, code `key_rejected`), not "assistant unavailable". The platform key is not tried, and `user_keys.last_error` is set. Test: Task 2 `test_user_key_auth_error_is_flagged_and_not_failed_over`, Task 3 `test_chat_with_rejected_key_says_so`.
2. **The email poller with a dead user key.** `email_configs.last_error` names the key problem. The email stays unprocessed, so it is not lost, and the next poll makes **no** LLM call while the key still has `last_error`. Once the key is re-saved or passes its test, the next poll processes the email. Test: Task 4 `test_poller_stops_on_user_key_error_and_resumes_after_fix`.
3. **Keys never leak.** `GET /api/keys` returns only `last4`. Nothing captured by caplog during save, test, a failed call or a poller failure contains the key. A provider 401 body that echoes the key comes back masked. Test: Task 3 `test_key_never_in_logs_or_responses`, Task 2 `test_failed_call_detail_is_masked`.
4. **The free allowance.** A keyless signed-up user gets the 21st question of the day refused with 402 `needs_key` ("Add your own key in Settings to keep using Lumen"), and the 21st invoice read is refused the same way. A user with a key for the role is never counted. Test: Task 5 `test_keyless_user_hits_question_allowance`, `test_invoice_reads_capped_without_vision_key`, `test_user_with_key_not_counted`.
5. **Provider quirks that would 400 every call.** Anthropic payloads carry no `temperature`. OpenAI payloads carry `max_completion_tokens` and no `max_tokens`/`temperature`. A stored model preference that left the list falls back to the list's first model. With no user in context, chains are byte-identical to today, so cassettes still replay. Test: Task 1 `test_adapt_payloads`, `test_platform_chain_unchanged`; Task 2 `test_retired_preference_uses_first`.

```python
        """Drop or rename request fields this provider rejects. Default: unchanged."""

class _OpenAI(Provider):
    # GPT-5+ are reasoning models: temperature other than 1 and `max_tokens` are rejected (checked 2026-10-16).
    def adapt(self, payload):
        payload.pop("temperature", None)
        payload["max_completion_tokens"] = payload.pop("max_tokens")
        return payload

    def reasoning_params(self, model, reasoning):
        return {"reasoning_effort": "low"} if reasoning == REASONING_OFF else {}


class _Anthropic(Provider):
    # OpenAI-compatibility layer: temperature < 1 is a 400 on Claude 4.7+; seed/response_format are ignored.
    def adapt(self, payload):
        payload.pop("temperature", None)
        payload.pop("seed", None)
        return payload

    def reasoning_params(self, model, reasoning):
        always_on = "opus" in model or "fable" in model
        return {"thinking": {"type": "disabled"}} if reasoning == REASONING_OFF and not always_on else {}

    def check_key(self, timeout: float = 8, key: str | None = None) -> tuple[bool, str]:
        try:
            resp = requests.get(f"{self.base_url}/models", timeout=timeout,
                                headers={"x-api-key": key or "", "anthropic-version": "2023-06-01"})
        except requests.RequestException as e:
            return False, f"could not reach anthropic ({type(e).__name__})."
        if resp.status_code != 200:
            return False, f"anthropic rejected the key (HTTP {resp.status_code})."
        return True, f"anthropic key OK ({len((resp.json() or {}).get('data') or [])} models available)."
```

```python
"""Users' own model keys (SPEC-BYOK): who the current request is for, and the chain their keys allow."""
from __future__ import annotations

import contextvars
import json
import logging
import re
from contextlib import contextmanager
from dataclasses import replace
from datetime import datetime

from sqlalchemy import select, update
from sqlalchemy.orm import Session

from llm.errors import LLMError
from llm.registry import BYOK_PROVIDERS, Entry

logger = logging.getLogger(__name__)
KEY_ENV = "KEYS_ENCRYPTION_KEY"
KEY_ERRORS = frozenset({LLMError.AUTH, LLMError.CREDITS, LLMError.CONFIG})
_ctx: contextvars.ContextVar[dict | None] = contextvars.ContextVar("llm_user", default=None)


@contextmanager
def for_user(user_id: str, engine):
    token = _ctx.set({"user_id": str(user_id), "engine": engine, "rows": None})
    try:
        yield
    finally:
        _ctx.reset(token)


def current():
    c = _ctx.get()
    return (c["user_id"], c["engine"]) if c else None


def _rows() -> list[tuple[str, str, dict]]:
    """(provider, decrypted key, {role: model}) for the current user; loaded once per request."""
    from models import UserKey
    from utils.crypto import decrypt_secret

    c = _ctx.get()
    if c is None:
        return []
    if c["rows"] is None:
        with Session(c["engine"]) as s:
            rows = s.scalars(select(UserKey).where(UserKey.user_id == c["user_id"])).all()
            out = []
            for r in rows:
                key = decrypt_secret(r.key_enc, key_env=KEY_ENV)
                if key.startswith("enc:"):  # encryption key changed: unusable, say so instead of sending it
                    logger.error("Stored %s key for a user can't be decrypted", r.provider)
                    continue
                out.append((r.provider, key, json.loads(r.models or "{}")))
        c["rows"] = sorted(out, key=lambda t: BYOK_PROVIDERS.index(t[0]) if t[0] in BYOK_PROVIDERS else 99)
    return c["rows"]


def user_chain(role: str) -> list[Entry]:
    from llm.client import registry

    chain: list[Entry] = []
    for provider, key, picks in _rows():
        listed = registry().byok(provider, role)
        pick = picks.get(role)
        listed.sort(key=lambda e: e.model != pick)  # the user's pick first, if it is still listed
        chain += [replace(e, key=key) for e in listed]
    return chain


def has_key(role: str) -> bool:
    return bool(user_chain(role))


def last4(key: str) -> str:
    return key[-4:] if key else ""


def mask(text: str, key: str) -> str:
    if not text or not key:
        return text
    text = text.replace(key, f"****{last4(key)}")
    for n in range(len(key) - 1, 7, -1):  # providers echo a prefix/suffix of the key
        for i in range(0, len(key) - n + 1):
            text = text.replace(key[i:i + n], "****")
    return text


def _set(engine, user_id: str, provider: str, **values) -> None:
    from models import UserKey

    with Session(engine) as s, s.begin():
        s.execute(update(UserKey).where(UserKey.user_id == user_id, UserKey.provider == provider).values(**values))


def mark_failed(provider: str, detail: str) -> None:
    c = _ctx.get()
    if c:
        _set(c["engine"], c["user_id"], provider, last_error=detail[:500])


def mark_ok(engine, user_id: str, provider: str) -> None:
    _set(engine, user_id, provider, last_ok_at=datetime.utcnow(), last_error=None)


def failing(engine, user_id: str):
    from models import UserKey

    with Session(engine) as s:
        return s.scalars(select(UserKey).where(UserKey.user_id == user_id, UserKey.last_error.is_not(None))).all()
```
